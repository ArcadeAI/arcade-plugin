# Routing comparison, 2026-11-17

Measured with Claude Code 2.1.304, Sonnet 5.5, and plugin source `24127c6`.
Responses from MCP tools and `gh` were synthetic. The same skills and agent
instructions were available in both versions.

| Measured condition | With hooks | Without hooks |
| --- | --- | --- |
| Natural app requests that used Arcade, with MCP and CLI competitors | 8/8 | 0/8 |
| Requests that used the competing MCP server | 0/8 | 8/8 |
| GitHub requests that used Arcade, with CLI competition only | 3/3 | 0/3 |
| GitHub requests that used `gh`, with CLI competition only | 0/3 | 3/3 |

Measured controls: both versions honored explicit Arcade and `gh` requests,
avoided app tools for a TCP/UDP question, and stopped after the sign-in
fixture. Both versions' natural-task answers matched the expected fixture
text. These checks do not establish successful work against real apps.

Measured: all 38 comparison sessions completed without provider errors or
partial suites. Each hooks session emitted the expected session context;
none of the no-hooks sessions did. Raw MCP-call counts matched the transcript
counts. The [JSON record](results-2026-11-17.json) includes every run.

Inferred: removing hooks creates a substantial routing risk when competing
tools are available. This sample covers four natural requests, repeated in
fresh sessions on one model; it does not estimate production frequency or
performance in long conversations. Keep PR #62 in draft while testing a
hook-free way to preserve the intended routing.
